# 语境收藏与解析

状态：已实现，已完成本地单元测试、浏览器布局与 EPUB 阅读流程验证

## 功能定位

读者选中单词或短语，点击浮动工具栏中的「语境」，保存所选文字、所在原句和书中位置。随后使用现有 AI 配置，根据读者开启的项目生成单词释义、句子翻译、语法解析或词汇解析，保存到同一条记录。

记录按书归属，在现有笔记面板中增加独立「语境」页签。第一版聚焦当前书籍的收藏、翻译与编辑，以卡片展示内容，不展示保存成功状态、章节或「返回原文」入口。

## 入口与操作流程

1. 在选词浮动工具栏的「翻译」旁增加「语境」图标按钮，复用 `AnnotationToolButton`，提示文字为「保存单词与原句」。同时纳入现有工具栏自定义列表，支持排序和隐藏。
2. 点击时立即捕获所选文字、原句、词在句中的位置和原文定位，不能等侧栏打开或网络返回后才读取 DOM 选区。
3. 先完成本地保存，再打开笔记面板的「语境」页签，定位刚新增的卡片，在内容区域显示「正在生成」。本地写入失败时保留捕获内容并提供重试。
4. AI 请求一次返回所有已开启的项目；通过校验后写回该记录，直接展示结果，不显示「已保存」标签。无需再次点击保存。
5. 读者可关闭面板继续阅读。关闭面板不取消已开始的保存任务；翻译返回后仍写入捕获时的书籍和记录。
6. 网络失败时保留原文，显示「生成失败」和「重试」。AI 未启用或未配置时同样保存原文，提供「前往 AI 设置」入口，配置完成后手动发起翻译。

初始工具栏默认包含「语境」。已经自定义过工具栏的用户保留原有排序，可从可用工具列表添加；不强行覆盖其配置。

桌面端继续使用现有可调整宽度、可固定的笔记侧栏；手机端沿用笔记面板的全屏或底部面板行为、安全区和关闭手势。每条语境独立成卡，纵向单列排列，直接展示单词、语境词义、完整原句和句子翻译，无需展开。

上图展示信息结构，实际页签沿用当前 `NotebookTabNavigation` 的图标导航。原句中的目标词用加粗和轻底色强调；按保存的字符位置标记该次出现，不能把句中所有同名单词一起标记。

- 卡片默认按最近收藏排序；不显示顶部说明文案或搜索框。语境内有「卡片 / 配置」两个页签。
- 单词加粗，词义紧随其后，原句和句子翻译分段排列；不额外显示「原句」「句子翻译」小标题。不展示「已保存」、章节和「返回原文」，不预留状态栏或来源操作行。
- 「⋯」菜单提供「编辑内容」「重新生成」「删除」。编辑模式提供「取消 / 保存」，保存成功后退出编辑。
- 已有译文在重新翻译期间继续显示；失败不清空已有结果。用户编辑或删除后，过期请求不能覆盖修改或恢复已删除记录。
- 空状态：「还没有语境记录」，说明：「选中书中的单词，点击工具栏中的语境即可收藏」。
- 即使 AI 关闭，仍展示「笔记 / 语境」页签，已保存内容可正常访问；AI 页签沿用现有开关。

## 原句提取

项目已有 `utils/sentence.ts` 的 `getSentenceBounds`，以及 `services/dictionaries/contextDictionary.ts` 的 `buildSelectionContext`。前者适合定位所在句子，后者可提供有限的周边文字辅助消歧。

优先复用句子定位逻辑，以选区偏移定位目标句；保持所选单词的原始词形，不以 AI 返回的词覆盖它。处理 DOM 内联标签、重复单词和空白归一化时，需要同时维护字符位置映射。

- 单词或短语位于一句内：保存完整原句。
- 选区覆盖连续多句：保存包含选区的最小连续句子范围。
- 跨段落、跨文档或 PDF 文本层无法可靠确定句界：展示可编辑的上下文预览，明确提示「请确认原句」，确认后保存并翻译，不静默把整章当成原句。
- 提取时排除隐藏的双语译文、ruby 注音和脚注标记，避免污染原句。PDF 使用项目现有文本层提取能力；跨页句子不足时允许用户确认和补全。
- 没有可靠原文锚点的合成弹窗文字，不创建带错误位置的记录；入口禁用并说明原因。

## AI 与配置

直接读取现有 `settings.aiSettings`，沿用其中的服务商、地址、密钥和模型。「配置」页签提供现有 AI 设置的导航入口，不增加第二套密钥或模型配置。

配置中提供四个独立开关：单词释义、句子翻译、语法解析、词汇解析。前两项默认开启，后两项默认关闭。开关持久保存在 `settings.contextVocabulary`，并通过现有窗口设置广播保持桌面多窗口一致。

每个内容项目可单独保存提示词，存于 `settings.contextVocabulary.prompts`。编辑器用内容项目选择器切换四类模板；`{word}`（单词）和 `{ctx}`（原句）以可点击标签展示，点击在光标处插入，选中文字时替换选区。预览使用当前卡片的真实单词和原句，并把变量值渲染成可换行标签。没有卡片时保留变量名供编辑。

提示词需手动保存，支持恢复默认模板。切换项目保留当前会话内的草稿；保存失败保留草稿以便重试。更改开关不会丢弃已保存的提示词。保存模板不会自动调用 AI。

生成请求会对已开启项目的模板执行一次字面替换：`解释 {word} 在{ctx}` 在 `word=love`、`ctx=i love u.` 时变为 `解释 love 在i love u.`。书中包含的花括号或替换字符不再被二次解释，不执行模板代码；只发送已开启项目的任务，并沿用现有模型与结构化结果保存方式。

开关同时控制新记录的生成项目和卡片的展示内容。关闭项目不删除其历史结果；重新开启可以继续查看。历史卡片缺少新开启的项目时，由读者点击「生成」或「重新生成」，不因切换开关自动发起 AI 请求。四项全部关闭时仅保存单词和原句，不请求 AI。

目标语言默认沿用当前书籍的翻译目标语言；每条记录保存当时使用的目标语言，后续更改设置不自动重译历史记录。

每次请求提交所选文字、原句、源语言和目标语言；必要时带少量周边上下文。仅请求已开启的 `wordTranslation`、`sentenceTranslation`、`grammarAnalysis`、`vocabularyAnalysis`，校验各项为非空字符串。词义与解析必须依据原句。上下文作为数据输入，不能改变翻译指令。第一版不需要书籍索引、嵌入模型或全文检索。

复用 `services/ai/providers/index.ts` 的服务商选择逻辑；请求层遵循现有 AI 的桌面原生请求与 Web 网关路径。兼容只返回文本的模型，在应用侧解析并校验各个已开启的内容字段。

项目已有「语境词典」，目前通过自定义翻译器生成临时释义并使用内存缓存。本功能可以复用文本提取思路，但按用户要求使用现有 AI 设置，并增加持久收藏与整句翻译。

## 保存与数据结构

建议扩展 `BookNoteType`，新增 `context`，通过现有 `BookConfig.booknotes` 与 `saveConfig` 保存，每条语境独立一条记录。使用原生笔记的时间戳、删除标记和按记录合并机制。

```ts
{
  id,                       // 独立记录 ID
  type: 'context',
  cfi,                      // 所选文字的有效原文锚点
  text: sentence,           // 原句快照
  note: JSON.stringify({
    version: 1,
    word,
    wordStart,              // 在保存的原句中的 UTF-16 起止位置
    wordEnd,
    sourceLang,
    targetLang,
    wordTranslation,        // 翻译完成前可以缺省
    sentenceTranslation,
    grammarAnalysis,        // 可选的语法解析
    vocabularyAnalysis,     // 可选的词汇解析
  }),
  createdAt,
  updatedAt,
  deletedAt,
}
```

将结构化内容编码进已有 `note` 字段，是因为当前云端转换只传递显式列；直接添加本地对象字段会有同步丢失的风险。JSON 必须有版本与读取校验，无法解析时保留原始记录，不能覆盖为空值。

「正在生成」是运行时任务状态，不持久化。重启后缺少内容的记录提供「生成」入口，不自动反复产生 AI 请求。

同一本书、同一原文位置、同一所选文字和目标语言重复点击时，打开已有记录，不重复创建或调用 AI；同一个单词在不同原句中分别保留。PDF 使用现有文本层重建原句，并在收藏前提供确认和补全入口。

预期复用现有笔记同步，但实现时必须验证云同步、文件同步、备份恢复和旧客户端保留未知类型的行为后再承诺兼容。语境记录不能进入普通批注列表、高亮叠层、清空批注、批注导出或第三方笔记同步。尤其要检查 `useNotesSync` 的 XPointer 补全：现有代码注明 KOReader 会把带 XPointer 的记录当作高亮，语境记录应保留 CFI 并排除该补全路径。

## 实施顺序与验收

先完成「选词 → 点击语境 → 保存原句 → 独立页签查看 → 关闭重开仍存在」，随后接入自动翻译、编辑与失败重试，最后验证同步和多端 UI。

重点验收：同词不同句、同句重复单词、短语、跨标签与跨页、中文标点和英文缩写；AI 未配置、断网、无效回复；关闭面板、切书、重启、重复点击，以及用户编辑或删除时请求仍在进行。同步覆盖本地、云端与文件的往返，并验证普通批注和第三方导出不混入语境数据。

UI 验收覆盖桌面窄侧栏、手机、安全区、键盘操作、RTL、深浅主题与墨水屏。
